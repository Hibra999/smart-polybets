Theta Trade — lay del favorito con salida anticipada

Status: DRAFT — validación en J1-J3 con sizing ≤ $10.
Evidencia de concepto (26 knockouts del WC, price history real de PM): +6.9% (salida 30min) a +21.4% (105min) BRUTO, 16W-10L a 90min. NO validado aún en Liga MX; el TP default es bruto de fees.

La estrategia en una línea

Comprar el NO del favorito al kickoff en mercados "Will X win" (resuelven a 90') y salir vendiendo antes de la resolución: cada minuto sin gol del favorito, el NO gana valor (decaimiento temporal + sobreprecio retail del favorito). No requiere modelo — requiere venue blando y disciplina de salida.

Paso 0 — Cómo obtener el id del mercado

python scripts/theta_monitor.py --list                # todos los winner abiertos (Liga MX)
python scripts/theta_monitor.py --list juarez         # filtro por substring (insensible a acentos)
python scripts/theta_monitor.py --list --tournament fifa_world_cup_2026
Imprime kickoff, question, bid/ask en vivo y el TOKEN NO de cada mercado. Dos formas de apuntar:
  • --market "<substring de la question>" — recomendado; resuelve token NO, tick y kickoff solo.
  • --token <TOKEN_NO> --kickoff <ISO UTC> — directo, sirve para cualquier mercado de Polymarket aunque el torneo no esté registrado.

Ciclo completo de un trade

# 1. (siempre en jornada) recorder juntando data en paralelo
python scripts/record_market_ticks.py

# 2. ENTRADA al kickoff — comprar el NO del favorito (carril CIO: riesgo + ledger)
python scripts/propose_bet.py --market "Will FC Juárez win on 2026-07-17?" \
    --outcome no --stake 10 --model-prob 0.55 --reason "theta lay J1"
python scripts/orders.py --approve <key> --live --confirm 10.00

# 3. MONITOREO + SALIDA — armar el CLI con el fill real
python scripts/theta_monitor.py --market "Will FC Juárez win on 2026-07-17?" \
    --entry 0.42 --shares 23.8 --live

Qué queda registrado (pase lo que pase)

  • Cada lectura (bid/ask/size/PnL) → tabla theta_tick; la sesión completa (entry, regla, salida, order_id, PnL) → theta_session. Ambas en data/<torneo>/market_ticks.sqlite (WAL — sobrevive cortes).
  • Si la venta falla tras los reintentos: imprime resumen + instrucciones (orders.py --list) y todo queda en la DB. Nunca te deja a ciegas.
  • Post-trade: la venta no pasa por el ledger → asentar con scripts/backfill_manual_trades.py.

Advertencias operativas

  1. El TP default (+5%) es bruto: el round-trip paga ~5% taker sobre ganancias. Calibrar el TP mínimo neto con los ticks grabados de J1 antes de dar tamaño.
  2. Gol temprano del favorito = gap en contra sin stop posible → sizing chico, muchas repeticiones (backtest WC: 16W-10L con colas de -0.46/share).
  3. Liquidez in-play de Liga MX: sin medir — J1 es la prueba. Si el sz del bid que imprime el monitor es menor que tus shares, la salida será parcial: achicar el sizing.
